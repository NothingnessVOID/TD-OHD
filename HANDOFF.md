## Single (1) texture — coloured Warp (current candidate)
- Asset: `src/features/transit-timeline/assets/definition-warp.png` (2400x84 RGBA, 324 KB). Displayed as an 800x28 tile (`background-size: 800px 100%`), so one horizontal repeat per 800px of bar.
- Generated by `scripts/build-definition-warp-texture.mjs`, which renders the **real** Warp shader from `@paper-design/shaders` (Apache-2.0) once in headless Chrome (WebGL2, `warpFragmentShader` + `vertexShaderSource` + the package's noise texture) and writes only the PNG. The package is a **devDependency of that script**, imported through a throwaway loopback static server; the app never loads it. `node scripts/build-definition-warp-texture.mjs` regenerates the same asset.
- Parameters (in the script): `shape: checks`, `proportion 0.45`, `softness 0.65`, `shapeScale 0.10`, `distortion 0.25`, `swirl 0.8`, `swirlIterations 10`, `scale 0.35` at bar height, colours `magenta #E01A6E / pink violet #B44BE8 / blue violet #5A5BF0 / green #12C58B / cyan #19BED8` interleaved with **fully transparent** slots.
- Transparency comes from the shader itself: gap colours are `00000000`, so the CSS orange base stays untouched in the gaps and every patch fades out of it. Composited with plain alpha (no `screen`/`lighten`): additive blending over a bright orange base bleaches the hues to white. The shader writes premultiplied RGB, so the script divides alpha back out before encoding.
- No squashing: the render is 28.57:1 and the tile is 28.57:1, and `u_scale` is multiplied by the same 3x, so the warped lobes are only cropped/scaled uniformly — never stretched. A 1200x84 band was rejected because 14.29:1 forced a 400px repeat that read as an obvious rhythm in long bars.
- Seam: alpha is feathered to 0 over 45 device px (15 display px) at both ends, so the wrap is a short pure-orange gap, not a colour jump.
- The count digit keeps its dark chip; the texture has irregular light and dark patches, so no bare ink colour is legible at every position.
- Superseded: the oil-film foil (`definition-foil.png` + `scripts/foil-to-alpha.py`) is deleted. The reason it was replaced is the form (directional film creases), not its compositing rules — plain alpha and the crop-don't-squash rule carried over.

## Single (1) glow veil (this round)
- Request: the Warp texture read as a flat print, not a glowing bar. The crisp texture is kept; a soft haze is layered on top of it.
- `timeline.css`: `.tl .tl-definition-bar[data-definition="1"]:not(.tl-definition-tick)::after` is an inset pseudo-element that repeats the **same** tile (`--tl-def1-tile`, default `800px`), `filter: blur(var(--tl-def1-veil-blur)) brightness(1.3) saturate(1.1)` with `--tl-def1-veil-blur: 6px`, `mix-blend-mode: screen`, `pointer-events: none`, `z-index: 1`.
- `screen` at low opacity is the point: bright areas of the texture scatter into their surroundings and the bar reads lit instead of printed. It is safe here because the blend only applies where the PNG has colour — the shader's void slots are fully transparent, so the orange base shows through the gaps untouched and nothing is screened over the whole bar. The layer is also blurred (peaks averaged down), boosted with `brightness(1.3)` so the scatter survives the low opacity, and run at `--tl-def1-veil: .24` light / `.32` dark.
- Measured on the rendered bar: mean luma 138.0→143.0 (light) / 144.5→151.1 (dark), peak luma unchanged (235.4), pixels with all three channels > 240 stay 0.00%. Earlier candidates were weaker or worse: plain alpha at 3px barely reads (the original complaint), and `lighten` at high opacity only lifted luma ~3 points.
- The earlier absolute note "any additive blend bleaches" was wrong as a blanket statement. It applies to the full-opacity texture composite (which does stay plain alpha); the low-opacity blurred veil is a different situation. Both the CSS comments and `docs/development/UI_COMPONENT_INVENTORY.md` were corrected to say so.
- Opacity is per theme only: `--tl-def1-veil: .24` light, `.32` dark (dark surfaces swallow the scatter). Nothing else changes between themes, so other skins need no rule.
- Ticks are excluded structurally by `:not(.tl-definition-tick)` — they already own `::before` (14px hit area) and `::after` (short-event cap). The Single tick look is untouched.
- The count chip keeps `z-index: 2` (`filter: none`), so the digit is painted above the veil and stays sharp. The veil lives inside the button (`overflow: hidden`), so bar geometry and hit area are unchanged.
- `@media (forced-colors: active)` sets the veil to `display: none`.
- 726a135d: the Warp colour field itself is blurred. It lives in `::before` (`inset: -6px 0`, so the filter does not fade the colour at the bar's top and bottom) with `background: url(definition-warp.png) 0 50% / var(--tl-def1-tile) 28px repeat` and `filter: blur(var(--tl-def1-veil-blur)) saturate(1.15)` at `--tl-def1-veil-blur: 6px`. There is no sharp texture underneath; only the orange base and the count chip stay crisp. That commit did not update this file, hence the corrected 6px above.
- `dev/definition-glow-demo.html`: version A (`.tl-def1-version-a`) switched the veil off with `content: none !important`, so A still renders exactly as before even though it shares `data-definition="1"`. That is still true, and A is now also excluded from the tuning selectors; the magnified preview takes its tile, blur and offset from the same panel controls at `--wt-scale: 2.25` (see the tuning-panel section). Caption sentence + `.tex-caption` describe the layer.

## Texture panel: two groups (this round, final)
- Final requirement: **both** the filter work (first task) and the real Warp shader (second task) live in one panel — 「Warp 形态 / 颜色 / 初始帧」 and 「外观」 — with one copy payload and one reset. The earlier attempt that dropped the filter group was superseded by this; there is still only one panel.
- Files: `dev/definition-glow-demo.html` (panel styles, the image swap, the look overrides, mount point), `dev/definition-warp-panel.js` (panel + live render), `dev/warp-texture.js` (shader parameters, uniforms, pixel post-processing), `scripts/build-definition-warp-texture.mjs` (imports the shared module; output unchanged). `src/features/transit-timeline/timeline.css`, the calculation code and everything under `src/` are untouched; nothing in `src/` imports any of this.
- Domain split, and it is stated in the panel itself: the Warp group changes the *form* (real shader output, re-rendered on every change); the 外观 group only changes how that output is shown (blur, brightness, saturation, glow strength, tile size). A CSS filter cannot move the warped structure, so the two groups are never presented as the same kind of knob.
- Live shader: `@paper-design/shaders` (devDependency) `ShaderMount` on an 800x28 box at `speed: 0`; every control calls `setUniforms` / `setFrame`, then one frame later `readPixels` + shared `compositeWarpPixels`, and the result is written to `--warp-preview-image` (2400x84 PNG data URL) on `.demo`. Slider input is coalesced (70ms + one rAF).
- Exact 3x: ShaderMount derives its render scale from the device pixel ratio, which does not always land on 3. The panel waits for the canvas to stop resizing, then corrects `minPixelRatio` once per measured width (bounded, converges in 1–2 steps) so the canvas is 2400x84; a screen denser than 3x keeps the larger multiple and says so in the meta line.
- Scope: only the image is swapped — `.demo .tl .tl-definition-bar[data-definition="1"]:not(.tl-definition-tick):not(.tl-def1-version-a)::before/::after { background-image: var(--warp-preview-image) }`. The look group then sets `--wt-blur` / `--wt-bright` / `--wt-sat` / `--wt-tile` (+ `--wt-veil` when pinned) on `.demo`, and `.demo .tex-tall { --wt-scale: 2.25 }` keeps the magnified preview proportional. A keeps `content: none` and ticks are excluded, so neither moves.
- Look defaults are the values `timeline.css` already uses (blur 6px, saturate 1.15, glow .24/.32 from the theme token, tile 800px, brightness off). They are written as *removals*: an untouched slider leaves no inline property, so the stylesheet stays authoritative and the default stays byte-identical. `brightness` only joins the filter chain once it leaves 1 (`data-wt-bright`), because `brightness(1)` alone still adds a pass.
- Shader group: 10 colour slots (picker + 「透明」 = alpha 0 = the orange base shows through), 底纹形状 (checks / stripes / edge), proportion, softness, distortion, swirl, swirlIterations, shapeScale, scale, rotation, frame. `u_scale` is the display-tuned value because ShaderMount divides the pattern space by its own `u_pixelRatio` (the offline script renders with `u_pixelRatio = 1` and multiplies by 3 — same structure, documented in `warpUniforms`).
- Frame is milliseconds (`setFrame` takes ms, the shader gets seconds). Playback is optional and paused by default; it is driven by the panel (a 100ms tick advancing `params.frame` + `setFrame`), so ShaderMount never leaves speed 0 and an idle tab has no animation.
- 「随机一组」 draws both groups at once and is deliberately constrained, because a free random draw would paint over the orange-gold base. Structural guarantees in `randomWarpParams` (`dev/warp-texture.js`): slot 0 always stays a gap, 3–5 opaque slots sit in one or two adjacent clusters, so at least half the slots remain transparent; the palette is the bar's own spectral family plus a warm and a lime patch (no dark or near-white entries). Ranges: proportion .2–.8, softness .35–.9, distortion .1–.6, swirl .2–1, swirlIterations 2–20 (integer), shapeScale .04–.35, scale .2–.6, rotation 0–360, frame 0–20000 ms in 10 ms steps; the 外观 group draws blur 3–12 px, brightness .85–1.35, saturation .9–1.5, glow .15–.6, tile 600–1100 px. Every value is snapped to the slider's own step, so the control, the output and the copied JSON always show the same number. A draw stops playback, pins the glow (it is a drawn value, not "follow the theme"), updates every input/output, re-renders immediately, persists, and is included in the copy and in reset.
- 「发光位置」 (`look.lightPosition`, 0–100% step 1, default 0) re-lights the Single bar's *base*, not the texture: the demo replaces the shipped 90deg centre-bright gradient (peak at 52%) with `radial-gradient(140% 180% at var(--wt-light-position) 50%, light 0%, warm 45%, deep 85%)` inside the bar's own box, so every bar — short, long, magnified — shares one direction. The top sheen layer is kept. 0% = bright at the left edge fading right, 100% = the mirror. It reaches B, swatch 1, the scene Single bars and the 2.25x preview; A, ticks and the 2–4 bars are untouched. The output names the position (`0% · 左侧起点`, `100% · 右侧起点`, otherwise 偏左 / 居中 / 偏右). 「随机一组」 deliberately leaves it alone (it is a user choice, not a look to shuffle) and reset returns it to 0%.
- One payload, one reset: the JSON is `{ warp: {…}, look: {…}, lookCss: "…" }` (`look.glow: null` means "follow the theme", `lookCss` carries the effective value ready to paste). Storage is a single dedicated demo key (`tdohd.definitionWarpTune.v1`, `STORAGE_KEY`); every value is range-checked on read (`normalizeWarpParams` + the look rows) and out-of-range junk is ignored. Colours are stored as compact 8-digit hex (`E01A6EFF` a colour, `00000000` a gap). 「恢复默认」 restores both groups and deletes the key — since the next round it restores the *selected preset*, see below; 「复制参数」 copies both groups.
- Copy reuses `src/lib/clipboard.js` `copyPlainText` (async API first, legacy `execCommand` fallback, no system dialog); the read-only textarea always shows the same JSON.
- Failure path: if WebGL2, the noise texture or the mount fails, the panel shows 「真实 Warp shader 没有跑起来：<原因>」, disables every control, switches its tag to 「shader 未运行」 and clears `--warp-preview-image` — the bars then show no texture at all rather than the old PNG, so a broken shader can never look like a working one. The 外观 group's sliders are disabled with the rest, since there would be no live texture to style.

## Selected preset + current-parameter arc comparison (this round, demo confirmation)
- The user's chosen parameter set is a **file**: `dev/warp-preset.json` (`name`, `note`, `warp`, `look`). It is the demo panel's baseline — a browser with no saved values opens on it. - Playback was only measured in headless Chrome. A 2400x84 read-back plus PNG encode every 100ms is the heaviest thing on the page and was not profiled on phone hardware.
- Touch dragging of the sliders and the colour picker on a phone, and iOS Safari's rendering of both, were not exercised; only Playwright viewport 390 wide.
- The panel is demo-only: no real timeline page was opened with tuned values, because the values are page-scoped custom properties and never reach `src/`.
- Baking a new parameter set into the app still means running `scripts/build-definition-warp-texture.mjs` after copying the JSON back into `WARP_DEFAULTS`; the panel does not write the asset. The 外观 group has no app-side counterpart to bake — it mirrors values that already exist in `timeline.css`.
- Glow veil: only default-light and default-dark were rendered. The other skins (including high-contrast) inherit the same two opacity tokens through `data-theme` but had no visual review. Forced colours were only checked in the emulator, not with a real OS high-contrast theme.
- Blur cost on a row full of wide Single bars, and on phone hardware, was not measured. The layer is static and clipped by the bar, but `filter: blur()` on many large elements has not been profiled.
- No real timeline viewport with a painted Single interval was captured with the veil; the evidence is the demo page, which imports the same shared `timeline.css`.
- Phone touch on short bars and keyboard focus order on the real page.
- A per-skin review across all ten skins; only default-light/default-dark were reviewed. High-contrast in particular has had no human review.
- Real performance and bar density over a full year-scale range.
- Any chart in the real timeline that actually paints a Single bar in the default viewport — the synthetic demo proves the shared CSS and the texture, and a probe on the real page confirms the asset resolves and decodes, but no real Single interval was on screen during this check.
- The 324 KB PNG is ~4x the old foil. It is cached and static; no measurement of first-paint impact.
- The tile repeats every 800px; the feathered seam was checked in a 1200px strip and is not visible, but very long bars still show a repeat.
- The green patch over orange can read olive at partial alpha; hue was brightened once after review and not re-reviewed by the user.
- The preset file is fetched with a relative URL (`./warp-preset.json`), so the demo page must stay next to it under `dev/`; the static build does not copy either file, and a 404 just falls back to the built-in parameters (not exercised beyond the disabled button path).
- The arc pair was reviewed on default-light and default-dark only; other skins inherit the same tokens but were not re-rendered. The arc layer is pure white at 20% by request — on a very bright skin its contrast is whatever A had, and no extra control exists to change it.
- Only default skin/theme screenshots were taken after the rename of the preset; no fresh pixel regression against the previous commit was run (the pair is additive and A/B computed styles were asserted instead).
- Full browser regression not run (AGENTS: run only after the user accepts).
