# 阶段 3：年度加载与缓存

## 实际修改

- manifest 扩展到 2021–2036 年。每年文件只含 13 点年初状态和事件；按计算签名、文件名及 SHA-256 校验。
- 年度文件按请求年份加载，同一请求复用并发加载；最多缓存 3 年且编码文件总量不超过 1,000,000 字节，另保留最多 4 份派生时间轴。缺失或损坏时仅对请求区间使用原计算扫描。
- 同时刻事件合并后再推导通道和中心，避免临时的零时长状态。出生盘计算按日期、时间、时区和时间未知标志复用。
- Worker 基本包约 95 KB；原引擎计算仅在回退路径动态加载。静态构建不依赖服务器端年度生成。

## 测试与性能

| 验证 | 结果 |
|---|---|
| `node scripts/verify-transit-events.mjs --all` | 16 年各约 2 万时刻，与同一引擎的直接结果差异均为 0；跨年年末状态接续正确。 |
| `node --test tests/annual-events.test.js tests/chart-cache.test.js` | 4/4 通过，覆盖同时刻重放、区间派生、7／28／7 加载去重、出生盘缓存失效。 |
| `node scripts/benchmark-transit-events.mjs 2026` | Node 26/macOS arm64：读 0.7 ms，解析 1.1 ms，重放 1000 次 3.5 ms；推导 7 天 6.1 ms、28 天 18.8 ms、365 天 83.1 ms；结束 RSS 128.6 MB。单次运行，非峰值或跨设备保证。 |
| `npm run build:pages` | 通过。 |
| 浏览器年度文件失效试验 | 人为把年度 JSON 请求改为 HTTP 503；390×844 视口仍生成 69 条可见轨道，只回退计算请求的 7 天并显示提示。 |
| 浏览器性能单次采样 | 桌面：冷 7 天 776.7 ms、热 28 天 55.5 ms、热 7 天 24.3 ms、一年 216.4 ms。390×844 视口且 Chrome CPU 4 倍限速：729.5、136.5、88.9、596.8 ms。各请求均只取 manifest 与需要的 2026/2027 年文件；这是本机模拟，不是手机实测。 |

浏览器可运行预览为本地开发地址 `http://127.0.0.1:5186`；本阶段没有独立界面截图，外观仍以阶段 1 截图为准。未验证 iOS/安卓实机、低内存设备和离线首次加载。若年度文件受损，回退扫描耗时仍取决于请求区间；已实现请求范围约束，未做长期压力测试。此提交可单独回退。
