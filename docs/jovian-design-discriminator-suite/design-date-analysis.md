# 已有 DesignDate 分钟标签的独立复核

33个不同出生UTC各有一个历史分钟标签，标签时区均为 **UNKNOWN**。从保存的秒级民用UTC和模型UT1数值时钟重新计算截断及四舍五入分钟，结果与继承字段完全一致。未加入时区位移或拟合偏移。

下表仅统计日历文本相同，不能当作已确认的物理时间匹配：

| 假设的显示时钟与分钟处理 | C1 | C2 | C3 | C4 | C5 | C6 |
|---|---:|---:|---:|---:|---:|---:|
| 模型UT1数值时钟，截断秒 | 33/33 | 33/33 | 33/33 | 33/33 | 33/33 | 33/33 |
| 民用UTC，截断秒 | 32/33 | 31/33 | 33/33 | 33/33 | 33/33 | 32/33 |
| 模型UT1数值时钟，四舍五入 | 11/33 | 11/33 | 12/33 | 12/33 | 12/33 | 11/33 |
| 民用UTC，四舍五入 | 10/33 | 10/33 | 11/33 | 11/33 | 11/33 | 10/33 |

**现有分钟标签没有无条件区分六模型的能力。** 模型UT1数值时钟截断后，33例的六模型均产生同一个已观测标签。民用UTC截断假设下有两例分钟分区，但显示时钟和时区没有确认，因此不能据此排除C2或支持其他模型。

| 出生UTC / 历史ID | 观测分钟标签 | 仅在指定假设下的差异 |
|---|---|---|
| 2023-07-04 12:50 / JDS-23 | 2023-04-04 08:27 | 民用UTC截断：C2为08:28，其余为08:27；模型数值时钟截断时六模型均为08:27 |
| 2025-01-19 22:57 / G2025-tight | 2024-10-25 01:26 | 民用UTC截断：C1/C2/C6为01:27，C3/C4/C5为01:26；模型数值时钟截断时均为01:26 |
| 2025-03-08 23:41 / JDS-07 | 2024-12-12 04:47 | 民用UTC四舍五入：C1/C2/C6为04:48，C3/C4/C5为04:47 |
| 2004-11-02 14:00 / JDS-20 | 2004-08-04 13:25 | 模型数值时钟四舍五入：C1/C2/C6为13:26，C3/C4/C5为13:25 |

四舍五入假设仅匹配10至12例，无法解释其余多数标签。四个假设都无法区分C3、C4、C5。第一行虽在民用UTC截断假设下区分C2/C1，仍缺少确认该假设所需的证据。

`designModelUt1NumericClock` 是库ΔT反解后的数值日历，在 `utc-as-ut1` 模型中代表逆调用数值输入；它不宣称民用UTC，也不代表IERS实测UT1。`designUtcFromTt` 是TT通过完整闰秒表转换的民用UTC。不能把未知时区的官方标签自动归入任何一种时钟。

本分析只复核已保存历史证据，与新增28例的Design Gate.Line评分分开。新增Jovian图面未观测到DesignDate，所以新增采集没有补充Design时间证据。分钟分辨率亦不能恢复精确TT根、黄经或官方ΔT实现。详细秒值、分区及来源SHA-256见 [design-date-analysis.json](design-date-analysis.json)。

复现命令（仓库根目录）：

```sh
python3 -B docs/jovian-design-discriminator-suite/scripts/analyze_design_dates.py
```

脚本固定读取继承数据，重新生成未封存的分析JSON；本次执行验证生成文件与原分析逐字节相同。
