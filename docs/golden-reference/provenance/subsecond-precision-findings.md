## Located astronomy-frame difference

Exact Sharp Swiss0.5.1 CorrectionPipeline.ToJ2000Equator (line492 onward) treats Swiss barycentric/ICRS input as already-J2000 coordinates. The common Sun/planet pipeline passes through aberration, precession and nutation without applying the ICRS-to-J2000 frame-bias transformation. Such a transformation is explicitly present in other code paths (planetocentric and some lunar/star paths). This is a concrete implementation difference from ordinary C Swiss flags258.

Two native probe longitudes at flags258:
2015-01-26T01:20Z:305.7499968177302degrees.
2025-01-19T22:57Z:300.1249969949901degrees.
Adding ICRS flag131072 to this Sharp path leaves both longitudes identical. Independent original C2.10.03 with flags258|ICRS131330 gives exactly the same printed double longitudes; C258 differs by about1.885e-6degrees, or approximately0.161seconds of Sun motion. Independent evidence: /tmp/td-ohd-golden-independent/tight-icrs-comparison.json.

This explains the small Sharp-vs-C astronomy difference for these two moments. It does not fully explain Jovian's discrete line/profile results, because the independent C258 Sun transition remains after the exact minute by0.110194seconds in2015 and0.095095seconds in2025. The black-box official product's numeric representation, rounding rules, and internal engine remain unverified. Neither float32 rounding nor a0.0625degree offset change is established from these cases.

## Place-bearing URL without saving records

8787 share parser accepts place/lat/lon/iana plus required d/t/tz. Example:
http://127.0.0.1:8787/?d=2015-01-26&t=01%3A20&tz=0&place=London&lat=51.50853&lon=-0.12574&iana=Europe%2FLondon

URL boot uses loadBirth(fromUrl,{save:false}), so it does not add synthetic records to the private local library. URL iana is validated and retained for presentation, but the calculation uses the supplied numeric tz. IANA offset calculation occurs when a city is selected in the entry form. Independent invocation of the installed timezone.js resolveUtcOffset confirmed Europe/London offset0 for2015-01-26 01:20 and2025-01-19 22:57. This supports reporting the numericUTC+0 baseline as consistent with the IANA result, without claiming the URL itself recalculates IANA.
