# TD-OHD 出生图 Golden Reference 专项审计

审计日期：2026-10-02 至 2026-10-03。官方对照为 [Jovian Archive 计算器](https://jovianarchive.com/pages/get-your-human-design-chart)。本地对照固定为 **8787 安装版**。本轮只调查，没有修改生产代码、安装版本、时区规则或 Mandala 常数。

**2026-10-03 新增第三对照源：**[SharpAstrology 作者官方 WebApp 九例实测报告](sharp-webapp/README.md)与[完整三方 JSON](sharp-webapp/comparison.json)。七例全部为 **Sharp 官方 WebApp = 8787 ≠ Jovian**，两个负对照三方一致；九例全部 234 项 Gate.Line 与 8787 相同。官方 WebApp 的 DE441 为 2026/04/18 构建，与 8787 的 2026/05/26 构建不同。本轮实测没有消除原有 Golden 差异。

## 结论

已通过两站实际浏览器操作复现 **7 个 Profile 不一致案例**，覆盖 1995、2005、2015、2025 年和 7 个不同 Personality Sun Gate。1985 年作为负对照也进行了官方核对。样本是主动构造的边界出生时刻，并非用户个人出生资料。

七例都是 **人格太阳和人格地球的 Line 提前/滞后一个爻**，Gate 不变；设计太阳和设计地球一致。Profile 直接跟随人格太阳 Line 改变。

**已定位到一个具体的 Sharp SwissEph 坐标转换遗漏**：普通 Sun correction pipeline 没有执行 ICRS → J2000 frame bias。当前 Sharp 声称使用默认 flags 258，但数值与原版 C Swiss 的 flags 131330（包含 ICRS）一致。此差异约相当于 0.16 秒太阳运动。改用独立 C 默认坐标后，七例中的两例全部 26 项 Gate.Line 与官方一致，另五例仍未匹配。后续再加入历史 DE431，能匹配三例，仍有四例未定位（见第 9 节）。进一步仅替换历史 ΔT 表的敏感性实验可使 2025 两例匹配，但 2015 两例仍未解释（第 10 节）。不能把这个局部缺陷称为全部差异的最终根因。

**单一 Mandala offset 修正已被正负对照共同排除。** 改动 `3.875°` 无法同时满足全部官方输出；不能据此提交 offset 补丁。

## 5. Root Cause：已确认与未确认分开

### 5.1 已确认的局部缺陷：坐标 frame bias 遗漏

Sharp SwissEph 0.5.1 的 `Application/Bodies/CorrectionPipeline.cs` 中：

1. `SunCorrectionPipeline()` 进入共用位置变换。
2. `ToJ2000Equator()` 将 Swiss 的 ICRS 原始向量当作已经是 J2000 赤道向量。
3. 经过光行差、岁差、章动后，没有在普通 Sun 路径执行必要的 ICRS→J2000 frame bias。

修复插入点应核对 `CorrectionPipeline.Apply<TFetcher>()` **L343 岁差之前**，与 C `app_pos_etc_sun` 的顺序一致；不应在 `ToJ2000Equator()` 中无条件转换。须尊重 ICRS flag、来源 DE number≥403、FrameBias 模型与速度旋转，避免其他路径重复 bias。源码精确位置和条件见 [独立审查](provenance/final-review.md)。

源文件固定在 NuGet 对应提交 `342a57997c1b987e7949acc98897c8b73d05939a`；见 [固定上游源码](https://github.com/CReizner/SharpAstrology.SwissEph/blob/342a57997c1b987e7949acc98897c8b73d05939a/Application/Bodies/CorrectionPipeline.cs#L343) 和 [源代码审查](provenance/subsecond-precision-findings.md)。

数值证据：90 个出生分钟点，Sharp 与原版 C flags `258|131072`（ICRS）的 Sun λ 最大差 `2.27×10⁻¹³°`；独立 C 默认 flags `258` 与 Sharp 相差约 `+1.885×10⁻⁶°`，对应约 0.16 秒。该吻合精度足以定位框架差异，不能用“同样都叫 Swiss”跳过它。

### 5.2 Gate/Line mapping 审计

固定 HumanDesign 1.2.0 `Utility/HumanDesignUtility.cs` 的 `ActivationOf()`：

```text
x = normalize360(longitude - 3.875)
gateIndex = floor(x / 5.625)
line = floor((x % 5.625) / 0.9375) + 1
```

实际代码使用 double，随后还有 Color / Tone / Base 的确定性细分。常数 3.875、5.625、0.9375 都可被二进制精确表示。规范化覆盖 0°/360°；没有 float32 窄化、额外 epsilon 或整分钟舍入。Profile 从两个已经取整的 Sun Line 直接得到，adapter 不重算 Line，也不把显示经度的舍入反写计算。

单个固定 offset 诊断（32 个官方记录、28 个唯一 UTC；P+D 共 64 个约束）无可行交集：

- 现有 Sharp：保持 2005-07-11 官方 P53.4 需 offset **>3.874997499485559°**；让 2015-02-04 得到官方 P13.3 需 offset **≤3.874996759837018°**。两者矛盾。
- 改为独立 C258 后仍矛盾：对应需 **>3.874999384406024°** 和 **≤3.874998644872903°**。

这排除了“用一个很小的 offset 改动修完所有案例”的方案。详见 [约束证据](independent/all-official-sun-offset-constraints.json)。后续新增 14 个邻分钟观测不会使已经空的交集重新非空。

### 5.3 已检查但不支持的解释

- UTC：本地有效 UTC 与官方可见 UTC、独立 Europe/London 历史 offset 一致；没有继续调查真太阳时或地点精度。
- UTC/JD 转换：全程 double；两例 DateTime→JD→DateTime 误差为微秒，Swiss 输入截去亚毫秒，不存在分钟级时间漂移。
- float32：虽然可让部分正例进入下一爻，也会错误地让 1985/1995 负对照进位，官方并没有这样显示。
- 3.9375° 替代：与 1985 年明确 Gate 切换负对照冲突。
- NONUT / TRUEPOS / NOABERR / Moshier / leap-aware UTC→UT1：针对两例的独立敏感性检查不能提供共同解释；未采用这些开关作修正。
- 官方前端残留 seconds：公开 widget 的 `formatDateTime()` 明确调用 `second(0).millisecond(0)`；重复同一案例结果稳定。不能归咎于表单随机秒数。
- Design root：七例差异在人格侧，设计侧一致；人格太阳不依赖 Design root。

### 5.4 剩余不确定性

官方服务不暴露原始黄经与内部 Design UTC。分钟级结果只能提供数值区间，不能唯一反推其内部精确坐标。已明确定位本地框架缺陷并排除单常数、通用进位和多个旗标解释；此处五例是同 DE441 对照的结果；第 9 节加入 DE431 后仍余四例，不能诚实地宣布完全根因已解决。继续诊断应针对 Swiss 版本/ΔT/时间尺度的具体差异，不应修改出生 offset 或采用按年/按案例拟合的常数。

## 6. 最小修复建议

1. **先锁定本轮 Golden 数据与负对照**，保持正式 8787 不动。
2. 在隔离计算候选中修复 Sharp Swiss 太阳路径缺失的 frame bias，或先用原版 C258 作为数值验证基准。转换必须匹配 Swiss 原始 ICRS 向量、flag 和变换顺序，不能简单把经度全局加 `1.885×10⁻⁶°`。需同时验证其他行星，避免重复 bias。
3. 验证原始 λ 再验证 Gate.Line；预期先消除 G1995-jun / G2005-jul20 两例。另五例保留为失败 Golden，继续核对内核版本和时间尺度。
4. **不建议当前修改 `HdOffsetToZodiac`、floor、出生时区或人为加容差。** 本轮对照已经证明一个通用 offset 无法满足所有正负样本。
5. Design root 的 tolerance 作为单独数值精度问题登记，只有拿到官方 Design-only mismatch 再处理其兼容性；不用于解释本轮人格侧差异。

## 7. 回归测试方案

- 固定 [golden-cases.json](golden-cases.json) 的官方 expected，而非当前 Sharp baseline。七例当前必须显示为 Golden failures，不能改 expected 来通过。
- 每例断言 Personality Sun/Earth、Design Sun/Earth 的 Gate.Line；Profile 等于官方；Cross 同时校验四个 Gate、角度/身份（不能只对名称别名）。
- 加入全部负对照：尤其 G1985-tight、G1995-tight、G2005-jul11，以及七例的前后一分钟。修正不得把它们错误进位。
- 增加映射单元测试：0°/360°，每个 Gate/Line 精确边界与 ±小量；独立检查 double / floor / Gate sequence。任何 boundary tolerance 必须有通用、可证实依据。
- 计算集成测试：分离 UTC转换、原始黄经、88°求根、ActivationOf、Profile、Cross；给 λ 数值配置明确误差界。
- 对七例实际 WASM 运行自动断言，避免 Native 正确但浏览器包旧版本；缓存 key 同时保留引擎版本及修正合同版本。
- Design-only 测试覆盖单爻与换 Gate 边界，并断言 solar arc 残差及 Design UTC 数值容差。不能只断言 Profile。
- 当前审计校验脚本只验证证据、UTC 和本地/官方差异登记的一致性；其通过不表示生产 Golden 通过。

## 9. 新增核对：历史 DE431 与当前 DE441

额外对照覆盖当前全部 **47 个官方原始记录 / 42 个唯一 UTC**（含统一 fixture 的 45 条和两份早期控制记录）。切换星历目录前调用 `swe.close()`，实际 loaded file path 与 DE number 已验证，返回 flags 必须与请求一致。数据来源、文件 hash 与 fresh process 复核见 [独立星历报告](independent/de431-vs-de441-report.md)。

| 配置 | 全部 26 项 Gate.Line 与官方一致的记录 | 七个 distinct mismatch 中匹配数 |
|---|---:|---:|
| C2.10.03 默认258 + 当前 DE441 | 39 / 47 | 2 / 7 |
| C2.10.03 默认258 + 历史 DE431 | 40 / 47 | 3 / 7 |
| C2.10.03 ICRS131330 + DE441 / DE431 | 37 / 47 | 0 / 7 |

历史 DE431 额外让 G1995-feb 匹配，但仍留下 G2015-tight、G2015-feb、G2025-tight、G2025-mar 四个独立差异，各只有人格太阳与人格地球的 Line 不同。重复拍摄的 2015 样本在上表按记录计数，不能把它们当成多个独立出生案例。

DE431 的1995年2月结果只比爻界高约 `2.258×10⁻⁹°`，相当约 **0.194 ms**。新进程可重复得到该数值，但这属于极窄边界，不能扩展为整个引擎已与官方一致。

这批 DE431 的变化使边界前移约0至9.3ms，余四例仍分别需约0.102、0.106、0.087、0.004秒的额外前移才能跨界。文件替换不能单独解决问题，也不能据匹配三例就推断 Jovian 使用DE431。当前安装的DE441没有被替换。

DE431情况下，单一Mandala offset约束仍无交集。原报告中32条早期快照的拒绝结论已被47条完整对照复核。

**当前最终定位状态：frame-bias遗漏已确认；独立标准坐标解释2例，标准坐标加历史DE431能匹配3例；其余4例仍待定位。没有任何候选修复被写入或验收到生产WASM。**

## 10. 最后核对：历史 ΔT 表的独立敏感性实验

历史来源采用 PyPI `pyswisseph 2.08.00-1` source distribution 内的完整 `libswe` 源码，tar SHA256 已与 PyPI 元数据一致核对。此前官方 Git 的一个 2.08 标签根目录实际上为 1998 旧文件、表到 1999，已明确排除，未用于本结论。

本项**没有运行完整旧 C2.08 内核**。实验固定 C2.10.03、标准258与DE431，只将 ΔT 表替换为历史2.08表并重现 Bessel 插值；不拟合数值。现代插值实现已在全部47条官方记录的出生与设计时刻和原版 `deltat_ex()` 核对，最大差 `7.11×10⁻¹⁵` 秒。全部26项激活和独立88°根重新计算。

| Case | 现代 ΔT 秒 | 历史表 ΔT 秒 | 差 秒 | 实验 P Sun / Profile | 与官方26项是否一致 |
|---|---:|---:|---:|---|---|
| G2015-tight | 67.672612632 | 67.672612632 | 0 | 41.4 / 4/1 | 否，P Sun/Earth 两项 |
| G2015-feb | 67.683215757 | 67.683215757 | 0 | 13.2 / 2/5 | 否，P Sun/Earth 两项 |
| G2025-tight | 68.994786402 | 72.025885875 | +3.031099474 | 60.5 / 5/1 | 是 |
| G2025-mar | 68.980201915 | 72.098379411 | +3.118177496 | 36.4 / 4/6 | 是 |

该组合在47条官方记录中有42条全部26项一致；余5条记录是**2个独立2015出生案例**及重复观测。七个 distinct mismatch 中有5例在此诊断组合下匹配。不能把记录数与独立案例数混用。

2025的结果支持“历史 ΔT 预测表可能参与差异”这一具体候选解释，**不能证明 Jovian 使用旧表、DE431或某个 Swiss 版本，也不能证明更旧时间模型更准确**。2015两例历史表与现代表数值完全相同，仍然无法解释。原始数据、程序与来源见 [历史时间表诊断](independent/historical-deltat-208-vs-21003.json)。

**最终状态：7例实际差异已经复现；frame-bias遗漏确认；标准坐标+历史星历+历史ΔT表的诊断组合可匹配5例，2015两例仍未定位。诊断匹配不是已经实施或发布的修复。当前8787依然保留原计算与七个Golden差异。**
