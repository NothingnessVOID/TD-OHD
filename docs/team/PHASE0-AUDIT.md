# TD-OHD Team：Penta / Wa 阶段 0 审计与实施蓝图

**状态：阶段 0 交付；仅审计与设计，尚未实现阶段 1。** 2026-10-09。审计基准：`NothingnessVOID/TD-OHD` 的 main 提交 `1e7fc7ad390e3e50e4087511a591399ca67e6022`。本文以 Jovian Archive、BG5 Business Institute 的公开正文、官方配图和公开样章为领域依据；它们说明的是该体系的内部规则，不等于这些理论已得到外部科学验证。

## 0. 决策摘要

当前 Team 页是一个以所有成员的 64 门并集推导九中心、通道、团队类型和职能的原型，**不具备可信的 Penta / Wa 专属计算口径**。第一阶段应先建立独立的 Penta 六通道、十二门结构投影，完整保留成员与 P/D 行星爻线来源，制作三列四层矩阵并修正身份、错误提示与状态边界。三列四层是本产品采用的**展示结构**：门的位置由 Jovian 官方图支持，但整张矩阵的版式、与 BG5 十二项 Business Skills 的逐格对应尚不能宣称官方认证。Wa 同样先做六条目录通道及明确人工编组的结构可视化；其人员自动分组、Alpha 自动判定、缺口工程和管理建议要等到逐条可核的更完整教材/授权资料。

### 本文的证据标签

- **O｜官方直接支持**：官方网页正文、官方配图或官方样章可直接看到的文字／结构。对样章**目录标题**只认定章节主题，不推定完整算法。
- **C｜可直接计算的图表事实**：输入图表中的门号、P/D、行星、爻线、成员 ID，以及以公开目录做集合运算得出的覆盖事实。计算事实**不自动升级成胜任力或组织行为**。
- **D｜产品设计决定**：UI 排版、状态分类、成员 ID、人工指定分组等，不标成领域定律。
- **U｜待证实**：公开资料尚不支持执行级规则；存储可预留字段，界面不自动推断。第三方转载不作为 O。

## 3. 阶段 1 可落地的数据与计算契约

建议使用 **编组 ID 与人物 ID 分离**：同一人物可进入不同团队或不同 Penta；同一团队的人物清单与具体 Penta 归属是两个层次。以下是接口草案，字段名称在实现时可细化，语义必须保持。

```ts
type TeamMember = {
  memberId: string;                // 本团队内稳定身份，不取数组序号/显示名
  personId: string | null;         // 已保存人物的 PeopleStore id；临时成员可为空
  displayName: string;             // 纯展示，同名允许
  origin: 'saved' | 'quick';
  chart: ChartContract;             // 只读计算结果
};
type Activation = {
  memberId: string;
  side: 'personality' | 'design';
  planet: string;
  gate: number;                    // 1..64
  line: number;                    // 1..6
  // 可选：chart 已有的 color/tone/base；阶段 1 不解释
};
type GroupAssignment = {
  teamId: string;
  revision: number;
  groups: Array<{ pentaId: string; label: string; memberIds: string[] }>;
  alphaMemberId: string | null;    // 仅显式人工指定；不能从图表推断
  unassignedMemberIds: string[];
  // 快照中引用人员 ID/出生信息版本，改资料后提示重新计算
};
type GateCell = {
  gate: number; row: 0|1|2|3; column: 0|1|2;
  status: 'present'|'absent';
  memberIds: string[];             // 去重，稳定排序
  activations: Activation[];       // 不去重，保留 P/D、行星、线
  evidence: 'official-topology';
};
type ChannelCoverage = {
  gatePair: [number, number];
  status: 'absent'|'selfComplete'|'crossMemberOnly'|'both';
  holdersByGate: Record<number, string[]>;
  selfCompleteMemberIds: string[];
  complementaryMemberPairs: Array<{ aMemberId: string; bMemberId: string }>;
  evidence: 'computed-coverage';
};
```

实现时需明确：`memberId` 由团队成员关系创建，绑定已有 `personId`；即使人重命名也不变。quick-add 若已成功写入 PeopleStore，采用 `saveTemporaryBirth()` 返回的记录 ID 回填 `personId`；同一个人物出现在一个 Team 中原则上拒绝重复，**只按 ID 判断重复**。未写入的人可获一次会话的 UUID，且不能被宣称为跨会话稳定；如允许持久团队，先提示存为人物再提交。若用户后来换了一份人物档案，创建新的成员关系而不是复用旧 ID。`pentaId` 是编组自身 ID，重排成员不重建 ID；每个成员最多属于当前 team 的一个 Penta，3–5 人为已成组，小于 3 人显示草稿，超出 5 人拒绝并解释。Wa 场景可先保存人工分组与未分配列表，不替用户自动将所有人塞入三个 Penta，也不强迫 16 人刚好全分配。

读取激活时遍历 `chart.gates.personality` / `design` 的**每个行星键**，取该激活的 gate/line，稳定排序为 `memberId,side,planet,gate,line`；验证空值、门号和爻线，并把来源不完整列为资料质量错误，不能由 `gates.all` 伪造 P/D。派生 `gateSetByMember`、`holdersByGate`、`activationsByGate` 三份索引：**出现状态按去重门号、贡献人数按去重成员、多重激活按原始记录条数**，三种计量在 UI 中分开。个人中心、类型、普通人际连接仅放附录式辅助统计，不能反馈到 Penta 的角色和领导判断。若部分 chart 不可算，明确指出成员及原因，阻止宣称完整团队结论；不要静默跳过造成错误成员数。

### 分层模块与显示契约

- `src/lib/human-design/penta-catalog.js`：冻结 12 门／6 通道与 row/column，官方 URL 在伴随文档中；`wa-catalog.js` 独立六条，不靠 `CHANNELS.filter` 猜目录。
- `team-activation.js`：ChartContract → 可验证的 `Activation[]`；纯函数、无持久化、无解释。
- `penta-structure.js`：成员列表 → 十二格、六条通道、来源与覆盖；显式 `scope: 'penta'`，只接受 3–5 人作正式结构。2 人可返回 provisional 覆盖预览但不贴 Penta 结论。
- `wa-structure.js`：明确 `GroupAssignment` → Wa 目录六条的覆盖和分组引用，默认不自动 Alpha/分组；9 人与 10 人提示各引 Jovian / BG5，不把“覆盖”称为 Wa 管理效能。
- `team-repository.js`：在 PeopleStore 之外持久保存 team/member/group ID、schemaVersion、修订号与人员引用；删除/变更档案时显示缺失引用和重新计算入口。阶段 1 可以仅实现本地团队草稿与 Penta 持久化，Wa 组织存储留给阶段 3；不要一开始污染 PeopleStore 人物 schema。
- `src/views/team.js` 做流程编排：选人 → 校验 → 算图 → 结构投影 → 显示；保存个人资料失败与计算失败分别报告，重复点击防并发。新增 `penta-matrix.js` 只负责 SVG/可访问描述，不承载领域判断；`wa-map.js` 阶段 3 再处理组织示意。

**SVG 主视图**：viewBox 驱动响应式缩放，三列四层的 12 个独立格、六条竖向通道线；用 fill/stroke 颜色标出门出现状态，用成员点／缩写标出贡献人数；点击/键盘进入详情列表看同一门的全部 P/D、行星、线及成员，线的“完整”仅表示门覆盖。底部同源 HTML 结构表为屏幕阅读器与打印、翻译提供降级；不靠红绿颜色独自传达状态。已有 11 Skin / 9 Center Palette 应通过现有语义 token 接入；与个人 BodyGraph SVG 解耦，不把多人的门叠印回个人图。浅/深色、390px 移动宽度和重名／高重复密度要真实验收。界面首屏只说“结构覆盖”，将未证实的技能/职位/建议隐藏或标为待核证，而不是以解释性语气暗示结论。
